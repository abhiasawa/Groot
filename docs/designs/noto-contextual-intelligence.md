# CEO Plan: Noto Contextual Intelligence — From Tool to Companion

## Vision

### 10x Check

Noto has built the **infrastructure** of an AI second brain but not the **experience** of one. 8 crons, 17+ database tables, 4 interfaces (WhatsApp, Telegram, Web Portal, Mobile App), multiple AI providers — but using Noto for a week doesn't *feel* like having a second brain yet.

The 10x version isn't more features. It's making existing features cohere into a **habit loop**:

**Capture → Immediate reward → Pattern detection → Narrative synthesis → "Whoa, Noto knows me" → Capture more**

The loop currently breaks at step 2: capture goes into a void until the next cron fires. The weekly report is a list, not a story. Pattern detection isn't wired. The "second brain" retrieval exists but users don't discover it.

### Platonic Ideal

**Week 1:** You send Noto a voice message. Within seconds, Noto responds with one line proving it *listened* — not generic "thanks" but genuine comprehension. By day 3, Noto says "I notice you mention work stress every evening but never in the mornings — is that a pattern you see too?" By day 7, your weekly report reads like a personal essay.

**Month 1:** You ask Noto "when was the last time I felt this way?" and it pulls up a conversation from 3 weeks ago with uncanny relevance. You share an article link and Noto summarizes it, files it, and references it two weeks later when the topic comes up.

**Month 3:** The weekly reports have become something you genuinely look forward to. They show you things about yourself you didn't notice. Noto feels less like an app and more like a friend who remembers everything.

### Platform Focus

**WhatsApp** is the primary interface. It's where the user already is.
**Mobile app** is the secondary visual interface — capture, chat, browse, track habits/mood.
**Web portal** exists but receives no new investment. All features target WhatsApp + mobile.

## Database Schema

Schemas defined in the /office-hours design doc (`abhishekasawa-office-hours-design-20260320-212613.md`). Summary:

### `pattern_insights` table
```sql
CREATE TABLE pattern_insights (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    insight_type VARCHAR(50) NOT NULL,
    -- Types: mood_shift, silence, commitment_stale,
    --        people_frequency, topic_shift, streak_milestone
    title TEXT NOT NULL,
    description TEXT NOT NULL,
    data JSONB DEFAULT '{}',
    severity VARCHAR(20) DEFAULT 'info',  -- info, notable, urgent
    surfaced BOOLEAN DEFAULT false,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_pattern_insights_user_type ON pattern_insights(user_id, insight_type, created_at DESC);
CREATE INDEX idx_pattern_insights_unsurfaced ON pattern_insights(user_id, surfaced) WHERE surfaced = false;
ALTER TABLE pattern_insights ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Service role full access on pattern_insights" ON pattern_insights FOR ALL USING (auth.role() = 'service_role');
```

### `commitments` table
```sql
CREATE TABLE commitments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    message_id UUID REFERENCES messages(id) ON DELETE SET NULL,
    commitment_text TEXT NOT NULL,
    detected_at TIMESTAMPTZ DEFAULT NOW(),
    last_referenced_at TIMESTAMPTZ,
    status VARCHAR(20) DEFAULT 'active',  -- active, stale, completed, dismissed
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE (user_id, commitment_text)
);
CREATE INDEX idx_commitments_user_status ON commitments(user_id, status, detected_at DESC);
ALTER TABLE commitments ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Service role full access on commitments" ON commitments FOR ALL USING (auth.role() = 'service_role');
```

**Note on mood data:** There is no `mood_entries` table. All mood data reads from `messages.metadata.detectedMood`. Two files query this nonexistent table and must be fixed:
- `src/lib/reports/weekly-synthesis.ts` — `gatherWeeklyData()` (fix in Phase 4)
- `src/lib/patterns/detector.ts` — pattern detection queries (superseded by `analyze.ts` in Phase 1)

**Disposition of `src/lib/patterns/detector.ts`:** The existing LLM-based pattern detector is replaced by the new SQL-based `analyze.ts` for scheduled analysis. `detector.ts` can remain for on-demand mobile display (if the mobile app uses it) but is not called by any cron pipeline. Mark as deprecated; remove once mobile is confirmed not using it.

## Implementation Phases

### Phase 1: Pattern Engine Foundation
**Dependencies:** None
**Files created:**
- `supabase/migrations/0XX_add_pattern_insights.sql`
- `src/lib/patterns/analyze.ts` — analysis functions (SQL-based, not LLM)
- `src/app/api/cron/analyze-patterns/route.ts`

**What it does:**
- Create `pattern_insights` table
- Implement analysis functions: mood shift (import `computeMoodTrend()` from `src/lib/journal/rich-context.ts` — export it if not already exported; generate `mood_shift` insight when return is `'improving'` or `'declining'`, skip `'stable'`/`'unknown'`), silence detection (weekday gap calculation, respects `getDeEscalationLevel()` from `src/lib/proactive/scheduler.ts`), topic shift (compare `memoryTags` this week vs 4-week avg), streak milestones (check against `MILESTONE_DAYS` from `src/lib/habits/tracker.ts`)
- Add cron to `vercel.json`: `{"path": "/api/cron/analyze-patterns", "schedule": "30 1 * * *"}` — current cron count: 8, this brings it to 9 (well within Vercel Pro plan's 40-cron limit)

**Cost model:** 4 of 6 analysis types are pure SQL queries (mood trend, silence, topic shift, streaks). Only people frequency and commitment staleness need data joins. **Zero LLM calls** in the daily cron — all analysis is SQL-based computation over existing metadata. Estimated runtime: <5s.

### Phase 2: Commitment Tracking + Instant Echo
**Dependencies:** Phase 1 (pattern_insights table)
**Files created:**
- `supabase/migrations/0XX_add_commitments.sql`

**Files modified:**
- `src/lib/ai/persona.ts` — add `detectedCommitments: string[]` to metadata extraction rules in system prompt
- `src/lib/ai/metadata-parser.ts` — parse `detectedCommitments` from `---METADATA---` block
- `src/lib/ai/groot-engine.ts` — after metadata extraction, if `metadata.detectedCommitments` exists, fire-and-forget UPSERT to `commitments` table (same pattern as profile fact upserts in the existing pipeline)
- `src/app/api/mobile/compose/route.ts` — UPSERT commitments alongside task processing
- `src/app/api/webhook/whatsapp/route.ts` — same commitment extraction for WhatsApp
- `src/lib/patterns/analyze.ts` — add commitment staleness check (query `commitments WHERE status='active' AND last_referenced_at < 7 days ago`)

**Instant Echo implementation:**
- A "capture-style message" is: a message classified by the existing intent classifier (`src/lib/memory/memory-router.ts`) with `MessageIntent` of `reflection` or `casual_chat` (when message length > ~50 chars, indicating a journal-like dump rather than a quick reply). Skip echo for `command`, `habit_checkin`, `query_memory`, `link_share`, and `store_memory` intents.
- When detected, the LLM system prompt switches to a short-response mode: "Respond with exactly ONE sentence acknowledging what the user shared. No questions, no advice, just proof you understood."
- This is a conditional branch in the response generation path in `src/lib/ai/groot-engine.ts`, not a separate handler
- Example: User says "Had a rough morning, the commute was terrible and I spilled coffee" → Noto: "Rough start — the commute and coffee spill sound like a frustrating combo."

**Commitment fulfillment detection (Expansion #7):**
- Add `fulfilledCommitments: string[]` to metadata extraction in `persona.ts`
- When detected, update `commitments.status = 'completed'` and include celebration in response
- Fulfilled commitments appear as wins in the weekly report

**Commitment extraction quality criteria:**
- A commitment is a concrete, actionable intent: "I want to start running," "I'm going to call Mom this week," "I need to finish the report by Friday"
- NOT a commitment: vague wishes ("I should probably exercise more"), hypotheticals ("It would be nice if..."), observations ("People should exercise")
- Add 3-5 positive and negative examples to the system prompt in `persona.ts`
- Commitment text normalized before UPSERT: `toLowerCase().trim()` to reduce exact-match collisions
- Estimated prompt token increase: ~100 tokens (minimal cost impact)

### Phase 3: Capture Habit Loop + Evening Synthesis
**Dependencies:** Phase 1 (pattern_insights for micro-synthesis data)
**Files modified:**
- `src/app/api/cron/daily-checkin/route.ts` — before composing morning message, read unsurfaced `notable`/`urgent` insights from `pattern_insights`. If mood_shift detected, reference it. Include capture streak: "Day N of journaling."
- `src/app/api/cron/midday-nudge/route.ts` — check for `commitment_stale` insights. Surface: "Remember when you said you wanted to [X]? That was N days ago."
- `src/app/api/cron/evening-reflection/route.ts` — include mood trend in context. After reflection prompt, append 1-line micro-synthesis: "Today: N thoughts, mood X/5, mentioned [topic] twice."

**Files created:**
- `src/lib/patterns/insights-reader.ts` — shared insight query utility (used by all upgraded crons)

**Capture streak:**
- Auto-create a `daily_capture` habit per user via idempotent upsert in `src/lib/ai/groot-engine.ts` after successful message processing. Guard with a `daily_capture_created` flag on the user profile to avoid per-message DB calls (check flag → skip upsert if already created).
- Reuse existing `habit_streaks` infrastructure from `src/lib/habits/tracker.ts` — `current_streak`, `longest_streak`, milestone celebrations
- Morning check-in references streak: "Day 14 of capturing your thoughts — here's what I've noticed..."

**First-week experience:**
- Days 1-3: Morning check-in includes explanation of what Noto learns ("The more you share, the smarter my weekly reports get")
- Days 4-7: First mini-insights if pattern_insights has data
- Day 7: First weekly report fires
- Implementation: check `user.created_at` age in cron logic, use different prompt templates for week 1

**Smart cron upgrade details:**
Each upgraded cron follows the same pattern:
1. Query `pattern_insights WHERE user_id = ? AND surfaced = false AND created_at > 7 days ago ORDER BY severity DESC, created_at DESC LIMIT 3`
2. Pass insights as structured context to the LLM prompt
3. After sending, mark referenced insights as `surfaced = true`
Template example (daily-checkin): "Context for morning message: [User has a mood_shift insight: 'Mood declining over past 3 days']. Reference this naturally, don't list it."

### Phase 4: Narrative Weekly Report + Second Brain Retrieval
**Dependencies:** Phase 1-3 (needs accumulated insights)

### User Journey — Emotional Arc

The habit loop (`Capture → Echo → Pattern → Narrative → Capture more`) has two make-or-break emotional moments marked with ★.

| Step | User Does | User Feels | Design Supports It With |
|------|-----------|------------|-------------------------|
| 1 | Sends first message | Curious, tentative | Instant echo (not silence) |
| ★2 | Gets 1-line echo back | "Oh, it actually listened" | Specific comprehension, not generic "thanks" |
| 3 | Morning check-in arrives (Day 2) | Surprised (it remembered) | "Day 1 — let's begin" + gentle context callback |
| 4 | Sends 3rd message (Day 3) | Building a rhythm | Echo reinforces the pattern |
| 5 | Morning check-in (Day 4) | "It knows me a little" | First micro-insight if data exists |
| ★6 | Day 7: weekly report | "Whoa, it sees me" (the hook) | Narrative prose, not bullets — feels personal |
| 7 | Day 14: habit streak | Pride, momentum | "Day 14 ✨" in morning + streak hero in habits tab |
| 8 | Stale commitment surfaced | Gentle accountability (not guilt) | Midday nudge, soft close (no question mark) |
| 9 | Completed commitment referenced | Celebration | "You did it!" in response + appears in weekly report |

**Critical design constraints:**
- ★ Step 2 (instant echo): If Noto replies with generic "thanks for sharing," the user feels unheard and won't return. The echo must prove comprehension by referencing specific content.
- ★ Step 6 (weekly report): This is the "whoa" moment. If it reads like a data dump, the emotional payoff dies. Must be narrative prose with a chapter title.
- Step 8 (stale commitment): Soft close with NO question mark. Questions create pressure; awareness creates reflection.

### Accessibility Specifications

**Touch targets (minimum 44px per Apple/Google HIG):**
- Tab bar items: 44px height minimum, equal width distribution
- Heatmap cells: minimum 30px × 30px with 2px gap. If screen width < 360px, show 4-week grid instead of 5-week. Each cell has invisible 44px tap zone (overlapping zones resolve to nearest cell).
- Mood chart data points: 44px invisible tap zones around each dot. Tap shows tooltip with date + score.
- All buttons, icon buttons: 44px minimum (already enforced by `ICON_BUTTON_SIZE` in tokens.ts)

**Screen reader (accessibilityLabel / accessibilityRole):**
- Capture streak hero: `accessibilityLabel="Day 14 capture streak"` (not just the number)
- Habit card: `accessibilityLabel="Exercise habit, 7 day streak, 5 check-ins this week"`
- Heatmap cell: `accessibilityLabel="March 15, checked in"` or `"March 15, no check-in"`
- Mood snapshot: `accessibilityLabel="Mood average 3.5 out of 5, improving trend"`
- Mood chart: `accessibilityLabel="Mood trend chart, 7 days, average 3.5"` with per-point labels on tap
- Tab bar: each tab gets `accessibilityRole="tab"` + `accessibilityLabel` + `accessibilityState={{ selected }}`

**Color contrast fix:**
- Amber `#FFBB2C` on cream `#F0EFEB` is 1.7:1 contrast — fails WCAG AA (needs 3:1 for non-text).
- Heatmap fix: use darker amber `#D4960A` for filled cells on cream background (4.1:1 ratio). Keep `#FFBB2C` for the progress ring on white card background (3.2:1 — passes for large elements).
- Empty heatmap cells: use `iconButtonBg` (#F5F4F2) with 1px `border` (#EAEAEA) outline for distinction.

**Design rules for states:**
- Empty states use NotoMascot + warm copy + primary action (never "No items found")
- Empty mood educates ("Noto reads mood from messages") rather than blaming ("You haven't tracked mood")
- Partial data: always show what loaded, never blank the whole screen for one failed request
- WhatsApp errors: silent fallback to normal messages — user never sees an error state

## Success Criteria

- [ ] Capture streak reaches 7+ days (habit formed)
- [ ] Weekly report reads as narrative prose, not a bulleted list
- [ ] Pattern Engine surfaces at least 2 non-trivial insights per week for an active user (someone capturing daily)
- [ ] A stale commitment gets surfaced within 7 days of going silent
- [ ] A completed commitment gets celebrated when referenced positively
- [ ] After capturing a thought, Noto's 1-line echo proves it understood (not generic "thanks for sharing")
- [ ] User can ask "when was the last time I felt [X]?" and get a relevant past conversation
- [ ] Link shared via WhatsApp gets summarized and stored within 30 seconds
- [ ] Mobile app shows habit streaks and mood trends without needing web portal
- [ ] No false-positive proactive messages — every outreach feels earned, not spammy
